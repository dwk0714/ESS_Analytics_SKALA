# 중복 파일·내용 점검

기존 분석 작업 폴더와 제출 저장소를 비교했다. 중복 파일 삭제는 보류하고, 제출에 필요한 파일과 이전 작업의 참조 관계를 구분했다.

## 파일과 내용 중복

| 중복 위치 | 확인 내용 | 정리 기준 |
|---|---|---|
| 기존 `artifacts/ess_eda/decision_log.md` ↔ 제출 `results/eda/decision_log.md` | 동일한 분석·선정 근거 기록의 사본 | 제출 저장소에서는 한 파일만 포함한다. 로그를 제출에서 제외하려면 01_EDA의 관련 링크도 정리한다. |
| 기존 `analysis/` ↔ 제출 `src/eda/` | `ess_batch_summary.py`, `ess_knee_eda.py`, `ess_deltaq_eda.py`, `ess_current_pattern_eda.py`, `ess_integrate_eda.py`의 계산 내용이 거의 같다. 주된 차이는 입출력 경로다. | 제출에서는 `src/eda/`를 유지한다. 기존 31번 노트북·보고서 생성 코드와 knee 전류 보완 코드가 `analysis/`를 참조하므로 기존 파일 삭제 전 해당 참조를 정리한다. |
| 기존 `artifacts/ess_eda/` ↔ 제출 `results/eda/` | 공통 경로102개 중100개가 동일하다. 동일 파일 합계는 약17.7MB다. | 제출 노트북에서 읽는 `results/eda/`를 유지한다. 기존 폴더는 31/32번 노트북과 이전 보고서 재현에 사용한다. |
| 기존 `31-ESSHealth-EDA.ipynb` ↔ 제출 `notebooks/01_EDA.ipynb` | EDA 내용이 상당 부분 겹친다. 준비 셀을 제외한 코드 셀13개가 동일하며 제출본은 경로와 실행 방식을 이식했다. | 제출에는 01_EDA를 사용한다. 기존 노트북은 이전 작업 보관용으로 구분한다. |
| README의 파이프라인 도표 ↔ `docs/pipeline.md`의 도표 | 동일한4단계 흐름을 두 곳에서 설명한다. | README 도표를 유지하고 상세 문서의 도표를 링크로 대체할 수 있다. 아직 삭제하지 않았다. |
| README 성능표 ↔ `results/performance_report.md`의 성능표 | 같은 실행 결과를 요약과 상세 보고서에 표시한다. | README는 프로젝트 요약, 성능 보고서는 보조 지표·진단 그림·오류 분석용이다. 두 문서 모두 유지할 수 있다. |

기존 작업 폴더는 제출 Git 저장소 밖에 있다. 제출 저장소만 업로드하면 위의 외부 원본과 제출 사본이 모두 GitHub에 올라가는 것은 아니다.

## decision_log 내부에서 반복되는 설명

- 첫 절의 상태 요약, 8절의 완료 여부 표, 마지막 DAY2 결과 절은 서로 다른 시점의 상태를 정리한다. 첫 절과8절은 DAY1 이력으로 명시했다.
- 보고서 개정 이력은10절 T08의 날짜별 변경점 표와 최종 검수 요약으로 축약했다. 앞부분과8절의 반복 개정 기록도 정리했으며 변수별 판단·지표의 역할은 유지했다.
- ΔQ·RMS·MAD 선정 이유는 9절, Ridge와 분할·평가 전략은 10절에 있다. README와 DAY1 보고서에도 핵심 내용을 요약했다.

## 계산 역할이 다른 파일

`02_feature_engineering.ipynb`는 특징 추출, `03_modeling.ipynb`는 학습·평가·보고서 생성 단계다. 두 노트북은 같은 모델을 각각 학습하지 않는다. 노트북과 CLI도 `src`의 같은 함수를 호출하는 실행 경로이므로 두 경로를 모두 실행할 필요는 없다.

`data/processed/cell_features.csv`는 모델 입력 표, `results/model_performance.csv`는 평가 결과, `models/ridge.joblib`는 저장 모델이다. 같은 데이터 흐름의 서로 다른 산출물이다.

## 문서 정리 범위

- 두 decision_log 사본, EDA 보고서·선정 근거·검토 문서, 설계·구현 기록의 문장을 수행한 분석 내용 중심으로 정리했다.
- 노트북의 설명과 보고서 생성 코드의 문구도 함께 수정했다. 기존 숫자·표·노트북 실행 결과는 유지했다.
- README·데이터 안내·모델 안내·결과 안내·파이프라인 문서를 실제 추출·학습·평가·보고서 저장 상태와 맞췄다.
- 기존 기록의 근거 파일은 프로젝트 내부의 역사 자료 경로로 복사해 연결했다. 원본 MAT·모델·성능 CSV를 변경하거나 학습·평가를 다시 실행하지 않았다.
